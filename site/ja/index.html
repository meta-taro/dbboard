10 のエンジンを 1 つの窓で。上の 3 つに加えて PostgreSQL、CockroachDB、 Neon、Supabase、MySQL/MariaDB、文書データベースの Cloud Firestore と MongoDB。

どんな画面か

これはモックではなく、架空のデータに対して実際に動かした画面です。 同じ 3 つのテーブルを手元で触りたい場合、データは scripts/demo-profile にあります。

2 つのデータベースを比べる

同じ種類の接続をもう 1 つ選ぶと、2 つのスキーマが食い違っている所だけが並びます。 片方にしかないテーブル、型・NULL の可否・既定値が違うカラム、一致しない主キー、 別の場所を指している外部キー、そして無い・別のカラムで張られている・片方だけ一意、 というインデックス。違う所しか出しませんので、300 テーブルあって違いが 1 つなら、 出てくるのは 1 行です。

型は、それぞれのエンジンが書くとおりに比べます。 VARCHAR(255) と varchar は、同じ意味かもしれなくても 違うものとして出します。見直す手間は一瞬ですが、見落とした違いは移行ごと失敗させます。 種類の違う接続どうしは、推測せずに断ります。

取っておきたいクエリと、100 行で終わらない表

エディタは前から実行したものを覚えていますが、その一覧はあえて使い捨てです。 名前を付ければ残ります —— 接続ごとに、ひと押しで戻せます。 置き場は接続情報の隣の saved-queries.toml で、窓自身の保存領域ではありません。 そちらは「サイトデータを消去」で空になり、設定のバックアップにも入りません。

テーブルを開くと、最後まで頁を送れます。頁は数えるのではなく鍵で辿る方式で、 前の頁の最後の行の直後から続きます。読んでいる間に行が増えても、 同じ行が 2 度出たり、頁の境目で消えたりしません。 どの頁も、最初の 1 頁より遅くなりません。

過去の版

VersionWindowsmacOS

古い版へ戻せます。戻しても接続情報は残ります。 うまく動かない版に当たったら、動いていた版を入れ直してください。 上の一覧はそのためにあります。各版は初回の起動時、何かを書く前に connections.toml を connections.pre-<版>.toml として控えます。 戻った先で、その版が確実に読めるファイルが見つかります。

ずっと古い版へ戻すときに 1 つだけ。入れる版より後に増えた種類の接続は、 その版には読めません。しかも古い版は、その 1 件ではなくファイル全体を断ります。 控えはそのためにあります。保存した資格情報はどちらの場合も影響を受けません —— ファイルではなく OS のキーチェーンにあります。

落としたものを確かめる

どのリリースにも、全成果物ぶんの SHA256SUMS.txt が付いています。 動かす前に、落としたものと突き合わせてください。 

# Linux / macOS
sha256sum -c SHA256SUMS.txt

# Windows PowerShell
(Get-FileHash .\dbboard-desktop_0.17.0_x64-setup.exe -Algorithm SHA256).Hash

AI エージェントから使う

dbboard には dbboard-mcp も入っています。画面を持たない MCP サーバで、すでに設定済みの接続を 標準入出力ごしに AI エージェントへ道具として渡します。読み取りは常に有効、 書き込みは接続ごとに明示して初めて開きます。権限の変更・TRUNCATE・ DROP は、どちらであっても通しません。アプリと同じ connections.toml と OS のキーチェーンを使うので、 資格情報の置き場が増えることはなく、秘密が通信に乗ることもありません。

このサーバを渡されたエージェントは、それが何かを尋ねられます。 about という道具が、何のための製品か、どの版が答えているか、 どのエンジンを話せるか、各版で何が変わったかを返します。 接続にもデータベースにも、あなたのファイルにも触れません。 答えはバイナリに埋め込まれているので、隣に何が置いてあるかではなく、 いま答えている当人を説明します。

上のアプリとは別に落とします。最新のリリースから dbboard-mcp-windows-x86_64.exe か dbboard-mcp-macos-universal を取り、動かさない場所に置いて、 1 行で登録します。 

# Windows (PowerShell)
claude mcp add dbboard --scope user -- "$env:LOCALAPPDATA/dbboard/dbboard-mcp.exe"

# macOS
claude mcp add dbboard --scope user -- "$HOME/.local/bin/dbboard-mcp"

Restart the agent afterwards — each client holds its own server process for the session. Setup, the twenty-two tools, the write policy and troubleshooting are in the dbboard-mcp の README. There is also a walkthrough in Japanese: Claude Code に自分の DB を触らせる.

動かす前に

このバイナリには署名がありません。忘れたのではなく、決めたことです —— 署名証明書は毎年払い続ける買い物で、この製品はそれをしません。 Windows では SmartScreen が「発行元不明」と警告し、 macOS では Gatekeeper が「開発元を確認できないアプリ」の確認を求めます。 どちらの警告も、毎回出るのが正常です。 上のチェックサムを確かめてから、通してください。
